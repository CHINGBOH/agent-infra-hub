# Skill 类型与 TDD 方法论

来源：superpowers writing-skills SKILL.md

## 三种 Skill 类型

### Technique（技术型）
具体的、有步骤的操作方法。
- 例：`condition-based-waiting`（异步测试等待模式）
- 例：`root-cause-tracing`（根因追踪）

### Pattern（模式型）
思考问题的心智模型。
- 例：`flatten-with-flags`（数据结构重构思路）
- 例：`test-invariants`（测试不变量）

### Reference（参考型）
API 文档、语法指南、工具文档。
- 例：办公文档 API 速查

## TDD 应用于 Skill 创建

Superpowers 的核心洞察：**写 skill 就是为文档写 TDD**。

| TDD 概念 | Skill 创建对应 |
|----------|----------------|
| 测试用例 | 用子 Agent 运行的压力场景 |
| 生产代码 | Skill 文档（SKILL.md） |
| 测试失败（RED） | Agent 在没有 skill 时违反规则（基线） |
| 测试通过（GREEN） | Agent 有 skill 时遵守规则 |
| 重构 | 封堵漏洞，同时保持合规 |
| 先写测试 | 在写 skill 之前运行基线场景 |
| 看着测试失败 | 记录 agent 使用的具体理性化借口 |
| 最小代码 | 只写解决那些具体违规的 skill 内容 |
| 看着测试通过 | 验证 agent 现在遵守规则 |
| 重构循环 | 发现新借口 → 封堵 → 重新验证 |

### 铁律

```
没有失败测试，就没有 skill。
```

适用于**新 skill** 和**对现有 skill 的修改**。

- 先写 skill 再测试？删掉，重来。
- 没有测试就修改 skill？同样违规。
- 不得有例外：不管多简单，不管多小的改动。

## 四类 Skill 的测试方式

### Discipline 强制型（规则/要求）
- 例：TDD、verification-before-completion
- 测试方法：
  - 学术问题：Agent 理解规则吗？
  - 压力场景：在压力下能遵守吗？
  - 组合压力：时间压力 + 沉没成本 + 疲劳
- 成功标准：在最大压力下遵守规则

### Technique 技术型（操作指南）
- 测试方法：
  - 应用场景：能正确应用技术吗？
  - 变体场景：能处理边缘情况吗？
  - 信息缺失测试：指令有漏洞吗？
- 成功标准：成功将技术应用于新场景

### Pattern 模式型（心智模型）
- 测试方法：
  - 识别场景：能识别模式适用时机吗？
  - 应用场景：能使用心智模型吗？
  - 反例测试：知道何时不适用吗？
- 成功标准：正确判断何时/如何应用模式

### Reference 参考型（文档/API）
- 测试方法：
  - 检索场景：能找到正确信息吗？
  - 应用场景：能正确使用检索到的信息吗？
  - 覆盖测试：常见用例都有覆盖吗？
- 成功标准：找到并正确应用参考信息

## 压力场景设计

对于 discipline 强制型 skill，压力测试至关重要。组合这些压力类型：

- **时间压力**："这是紧急情况，快点"
- **沉没成本**："我们已经写了这么多代码了"
- **权威压力**："我是高级工程师，相信我"
- **疲劳**：经过长时间对话后的请求
- **表面简单**："这太简单了，不需要那么多步骤"

## 封堵理性化漏洞

Discipline skill 需要主动封堵 agent 的借口。方法：

### 1. 明确封堵每个变通方式

```markdown
❌ 弱：写了代码才写测试？删掉它。

✅ 强：写了代码才写测试？删掉它，重来。
**没有例外**：
- 不能保留作"参考"
- 不能"边写测试边调整"
- 不能"只看一眼"
- 删除意味着彻底删除
```

### 2. 添加"精神 vs 字面"防御

```markdown
违反规则的字面就是违反规则的精神。
```

### 3. 构建理性化表格

从基线测试中收集 agent 使用的借口：

| 借口 | 现实 |
|------|------|
| "太简单了不需要测试" | 简单代码也会出错。测试 30 秒够了。 |
| "我先做，回头再测" | 先做的测试证明的是你现在实现的东西。后做的测试只是验证现状。 |
| "测试后做能达到同样效果" | 错。先写测试问"应该做什么"，后写测试问"现在做了什么"。 |

### 4. 添加红旗清单

```markdown
## 红旗——停下，重来

- 代码先于测试
- "我已经手动测过了"
- "测试后做能达到同样目的"
- "这是精神而非字面"
- "这次不同，因为..."

**所有这些都意味着：删掉代码，用 TDD 重来。**
```
